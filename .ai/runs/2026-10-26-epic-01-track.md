- 1.7: callback calls `accountService.resolveGithubAccount(profile)` — it already reconciles operator (new accounts are created with effective roles, no event); `GithubAccountConflictError` (409 `GITHUB_ACCOUNT_CONFLICT` → `github_account_conflict`). On a lost insert race it calls `em.clear()` on the request-scoped `em` and re-reads once, so the callback should not hold other managed entities in that scope. Sign-out route: `accountService.signOut(userId)` (no-op for an unknown user).
- Unit tests for services using `em` use an in-memory fake (`findOne` by equal fields, `create` pushes, `flush`/`clear` mocks) inline in `account.service.test.ts`; extract to a shared helper when a second service needs it. `UniqueConstraintViolationException` and `DEFAULT_ROLES` are now value exports of `@devmentor/db`.
- 1.7: `dm_oauth` reuses `signToken`/`verifyToken` (`core/src/security/jwt.ts`, `aud: 'oauth-state'`) and `authCookie`/`clearAuthCookie`/`readCookie` (`core/src/http/cookies.ts`); both are internal to core (not exported) — the OAuth state helper belongs in core next to them. GitHub start returns `{ externalLocation }` from `redirectHandler` (spec row updated).
- Logger: redacting `*.code` (spec) also hides `err.code` of logged errors (e.g. Postgres `23505`); revisit if it hurts debugging (e.g. a custom `err` serializer keeping the code).
- 1.7: `GithubOAuthService` (`cradle.githubOAuthService`) — `buildAuthorizeUrl({ state, codeChallenge, login? })` returns a `URL` for `{ externalLocation }`; PKCE helpers `createPkceVerifier`/`pkceChallenge` live in `core/src/security/pkce.ts` (internal, next to the OAuth state helper).
