- 2026-11-24 — A control that "does not look clickable" (#79) is a design-token bug as much as a markup one: the unchosen option used `border-border`, the decorative-line token, so it read as a badge; a control outline uses `border-input` (WCAG 1.4.11), and hover styles go behind `has-[:enabled]` so a locked option does not invite a click. In QA, headless browsers do not apply `:hover`, sub-second busy states need network throttling, and dark mode has no user switch, so these stay human checks (`.ai/qa/knowledge-base/risk-hotspots.md`).
- 2026-11-23 — Access-control probes: a denial counts only with a valid payload and both accounts proven signed in. Our first walk "passed" cancel and report as 400 (missing `expectRefund`, message under 20 chars), which is validation, not authorization. Roles that combine create self-dealing paths no single-role test sees: an operator who was also a mentor could resolve the dispute on their own booking and release their own payout (T-06, fixed). The operator role is reconciled from `OPERATOR_EMAILS` on every request, so granting it with SQL does nothing; make an allowlisted operator a mentor instead (`.ai/scripts/qa-access-control.mjs`).
- 2026-11-23 — A decision made in a spec does not reach the brief by itself: the brief said "no automatic refunds" and "Q01 open" for weeks after the code shipped both, and eight done specs sat outside `implemented/`. When a spec answers a brief question or overrides a rule, the same PR updates the brief (decision row, closed question, superseded rule), and the implementation PR moves the spec. `check:agents` checks length and paths, not meaning; a read-only agent consistency pass at each retro does (`.ai/context/2026-11-23-lesson-15-retro.md`).
- 2026-11-21 — Money that leaves the platform (spec `.ai/specs/implemented/2026-11-21-mentor-payouts.md`): Stripe idempotency keys live about 24 h, so "retry with the same key" can pay twice after a long gap, and inside the window it only replays a stored error. Claim the payout (`transferring`) under a row lock, look the transfer up by `transfer_group` before every create, write the result only `WHERE status = 'transferring'`, use a new key (`…-<attempt>`) after a definite refusal, and freeze the amounts on the row. Refunds follow the same rule: a timeout leaves `requested`, never `failed` — nobody refunds by hand on a guess. A redelivered `checkout.session.completed` must ignore every terminal status (it turned a cancelled, refunded booking into `payment_orphaned`). The Stripe stub must replay errors for a key, refuse changed parameters (`idempotency_error`) and be able to drop an answer after doing the work, or none of this is tested.
- 2026-11-21 — PostgreSQL CHECK passes on NULL: `(decision = 'declined') = (comment is not null)` lets a waiting row (`decision` null) carry a comment — use `is not distinct from`. A state machine the service enforces (one waiting version, one approved) also needs partial unique indexes, and the service must read the state *after* taking the row lock, inside the same transaction; a read before the lock turns a lost race into a 500. A polling cursor on `created_at` (set in the app) or a random id skips rows that commit late — use a `bigint generated always as identity` and serialize writers of one parent row (MikroORM: `.generated('identity')`, plus `.autoincrement().columnType('bigint')` only to make it optional on create).
- 2026-11-21 — **Never let CI be the first run of the integration suite.** Six PRs in a row (#56, #58, #61, #63, #65, #67) failed only in CI because no one ran `npm run test:integration` before pushing; each cost a 6-minute CI round trip. Before every push that touches pages, copy, nav, selectors or a business rule: (1) `rg` the old copy, link counts, selectors and the changed rule in `packages/app/integration/` and update what it breaks (#67: the overlap test relied on one mentee holding two times, which the fix forbids); (2) ask the owner to run the affected files locally (`! npm run test:integration -- <file>`; it needs Docker and runs outside the agent sandbox). Tests that share one actor across `it` blocks (the booking suite's `menteeCookie`) break when a rule about that actor changes — give such cases their own actor. When watching CI, wait for a run whose `headSha` is the pushed commit (`gh run list --branch <b> --json headSha,status`): `gh pr checks --watch` right after a push still sees the previous run or none.
